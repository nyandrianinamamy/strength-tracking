# TestFlight CI golden-image repair

The `v1.0.31+310` release run passed all 314 app tests and 489 engine tests, then failed both heatmap golden comparisons by 450 pixels (0.09%). The native and upload jobs did not run.

The diagnostic workflow run `34217580619` reproduced the same failure on macOS 15 ARM64 with Flutter 3.41.9. Its captured images show that all differing pixels are within the fixture captions at x286–506, y2–14. Every heatmap pixel matches the reference. The same Flutter version and architecture pass locally on macOS 27; setting `CI=true` locally does not reproduce the failure.

The fixture requested bold Ahem, although the bundled test font only provides regular weight. Synthetic bold and fractional font metrics made the caption edges depend on macOS text rasterization.

The fixture now uses regular Ahem at 10 pixels, a fixed line height, explicit color, and integer positioning. Four-pixel letter spacing preserves the original caption widths. The 17-pixel caption slots and the heatmaps' y25 starting position are unchanged. Both caption labels have semantic assertions, and the whole-image comparison remains exact: no tolerance, skips, masks or cropping.

Both local golden tests pass with the corrected references. Each reference changes 738 caption pixels and zero heatmap pixels. The captions now contain only the foreground and background colors, with nine exact 10×10 glyph rectangles and no partially covered edge pixels.

CI now uploads golden failure images as verification artifacts. A manual `quality_only` option runs the same checks without signing or uploading, and generated failure images are ignored by Git.

Local diagnostic evidence is under `build/ci-repair-310/`: `ci-original-diff.json`, `caption-pixel-verification.json`, the CI images, and reproduction/verification logs. The correction is prepared for a new release tag, `v1.0.31+312`; the failed `v1.0.31+310` tag is retained.
