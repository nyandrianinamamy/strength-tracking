# TestFlight CI golden-image repair

The `v1.0.31+310` release run passed all 314 app tests and 489 engine tests, then failed both heatmap golden comparisons by 450 pixels (0.09%). The native and upload jobs did not run.

The diagnostic workflow run `34217580619` reproduced the same failure on macOS 15 ARM64 with Flutter 3.41.9. Its captured images show that all differing pixels are within the fixture captions at x286–506, y2–14. Every heatmap pixel matches the reference. The same Flutter version and architecture pass locally on macOS 27; setting `CI=true` locally does not reproduce the failure.

The fixture requested bold Ahem, although the bundled test font only provides regular weight. Synthetic bold and fractional font metrics made the caption edges depend on macOS text rasterization.

An initial correction used regular Ahem at integer glyph bounds. It passed locally but the `v1.0.31+312` CI run still differed by 288 caption-edge pixels. The new CI images again showed zero differing heatmap pixels: even regular Ahem remained dependent on the macOS text renderer.

The final fixture keeps front/back labels in semantics and paints only the component under test. `BodyHeatmap` itself paints paths, not text. The original 17-pixel label slots and the heatmaps' y25 starting position are unchanged. Both labels retain semantic assertions, and the whole-image comparison remains exact: no tolerance, skips, masks or cropping.

Both local golden tests pass with the corrected references. Pixel comparisons against the committed build310 references and the actual CI312 images show zero heatmap changes. All changed pixels are inside the fixture's original 17-pixel label slot. No production source changed.

CI now uploads golden failure images as verification artifacts. A manual `quality_only` option runs the same checks without signing or uploading, and generated failure images are ignored by Git.

Local diagnostic evidence is under `build/ci-repair-310/`: `ci-original-diff.json`, `ci-312-diff.json`, `phase2-pixel-verification.json`, the CI images, and reproduction/verification logs. The correction is prepared for a new release tag, `v1.0.31+313`; the failed tags remain unchanged.
